# 项目性能优化总计划

> 执行说明：实施时使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，逐项执行并记录验证结果。计划最初只生成方案；2026-09-30 已按后续执行指令完成 01、02，其余专项尚未实施。

**目标：**限制大结果累积，保证连接池繁忙时仍可取消查询，减少重复数据库访问，并改善长 SQL、宽表、导出及启动交互。

**架构：**保留 React/Zustand → Tauri 命令 → Rust 数据库适配层。复用现有结果预算、连接取消、元数据缓存和虚拟化基础，按六个可独立验收的工作流逐步修改。

**技术栈：**React 18、TypeScript、Zustand 5、Ant Design 5、Monaco、Vite 8、Tauri 2、Rust/Tokio；MySQL/MariaDB、PostgreSQL、SQLite、SQL Server、ClickHouse。

**需求依据：**2026-09-30 当前代码审计与用户要求生成性能优化计划；本文件的范围、边界、基线和验收约定作为六份专项计划的共同规格。

## 全局约束

- 默认在当前分支修改；用户未明确要求新建分支时不得新建分支或另建工作树。
- 禁止在循环遍历中查询 SQL。批量目录与完整行读取必须采用集合 SQL；`Promise.all(map(查询))` 和把逐项查询包装为异步任务均不合规。消费同一次 SQL 返回的结果流不属于重新查询。
- 文档、界面和提交描述使用简体中文；获准提交时遵循英文 type 加中文描述的 Conventional Commits。生成计划不触发提交、推送或发布。
- 不自动安装或升级依赖；先使用已安装的运行时、驱动和库。新增依赖必须有具体必要性并记录影响。
- 保留现有只读限制、主键证据、无损整数、日期与二进制展示、SQL 执行顺序、错误与取消语义。
- 不丢失 SQL 草稿和待提交编辑；不得因缓存淘汰自动重跑 SQL，不得静默截断后把部分结果视为完整成功。
- 自动化验证使用合成数据、内存 SQLite 或受控测试替身。真实网络数据库验证使用隔离测试实例，不连接业务库。
- 日志和基准只记录时间、数量、字节和随机运行标识，不记录凭据、完整 SQL 或结果内容。

## 执行顺序与文件协调

1. 先实施 02：范围小，解除池满时无法及时取消的资源依赖。
2. 实施 01，再实施 03；二者与 02 都涉及 `src-tauri/src/commands/data.rs`，同一工作区避免同时编辑该文件。
3. 04 可在其他任务不改 `SqlEditor.tsx` 时独立执行；05 和 06 都涉及该组件及 `TableData.tsx`，按顺序落地。
4. 06 使用 01 的缓存保护租约；若提前实施，只交付不依赖租约的二进制写入/编码模块，调用方集成等待 01。
5. 可并行开展不同模块的只读审查、夹具设计和基准准备；共享源文件的修改串行执行，不通过擅自新建分支规避冲突。

专项计划中的新增阈值均为拟实施默认值，不是当前配置。01 使用 128 MiB 的缓存估算软预算；受保护结果可暂时超预算，必须报告无法回收状态，不声称这是进程 RSS 上限。02 的取消网络操作总超时为 2 秒，连接清理另设 2 秒。03 保留现有缓存容量和寿命，先修复复用与失效语义；批量目录请求去重后最多 256 个名称，空输入零查询，超限明确拒绝、不循环拆分。04 的同机调优目标为 1 MiB 热补全及末尾编辑 p95 低于 15 ms；05 的宽表记录转换分配量目标下降至少 70%，均为待验证目标，不是本次已实现收益或跨机器 CI 门禁。

## 审查重点

1. 大字段预算失败后不能污染连接池；由 01 的早停与后续查询测试验证。
2. 迟到响应、执行 ID 复用、断线和切标签不能作用于新状态；由 01/02/03/04 的代次与生命周期测试验证。
3. 缓存淘汰不能抹掉未提交编辑或导出所用结果；由 01 的租约和 06 的切页/淘汰并发测试验证。
4. UI 优化不能丢失隐藏主键、选择、复制或跨页同步选择；由 05 的交互回归验证。
5. Windows 路径、中文文件名、错误写入和大整数导出不能退化；由 06 的原始请求、文件和工作簿测试验证。

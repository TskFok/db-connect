# 查询结果与缓存内存限制

SQL 编辑器、执行计划查询、表浏览和完整字段回查使用统一预算，定义在 `src-tauri/src/db/result_budget.rs`：

- 最多 **100,000 行**，恰好达到上限可正常返回。
- 最多 **32 MiB**，按列名数组和行矩阵的紧凑 JSON UTF-8 字节数计算，包含转义、空值和数组分隔符。预算不等同于进程堆内存上限。
- 超过任一预算即返回中文错误，不把截断数据作为完整结果展示。可通过减少列、限制返回行数或缩小查询范围重试。

表浏览的页大小必须为 **1–10,000**，入口在获取连接前拒绝非法值；完整字段回查仍保留 100,000 行防线。MySQL 表格中的大字段预览按实际预览标记计费，复制或导出时回查的完整字段按实际完整值计费，因此能浏览预览不代表完整导出一定在预算内。主键集合采用一次集合查询，不通过逐行查询绕开上限。

PostgreSQL 使用 `simple_query_raw` 逐条读取消息，直接生成最终行矩阵；MySQL、SQLite 和 SQL Server 逐行转换并检查预算。读取已有结果流不会为每行额外执行 SQL。

PostgreSQL 的取消信号会唤醒等待下一行的读取任务。超限或取消时发送取消请求（清理最多等待 2 秒），并移除该池连接；正常完成后禁用旧取消句柄，避免影响复用连接上的后续查询。MySQL 出错时关闭连接，不为清理而继续排空超限结果。SQL Server 结果读取失败时也关闭并淘汰连接，保留原有连接池容量限制，避免后续查询为了复用连接而继续排空旧结果。

ClickHouse 同时设置服务端行数与字节数上限，并对 HTTP 响应累积字节设置本地上限；响应包含元数据和统计信息，因此可能比最终行矩阵预算更早拒绝。解析后的结果仍需通过共享预算。

前端保留后端返回的二维数组，以总行数驱动分页，仅把当前页转换成表格记录；导出继续使用完整的已接收结果。

## 跨标签与跨语句共享缓存

`src/utils/resultCacheBudget.ts` 中唯一的应用级协调器使用 **128 MiB** 估算软预算。SQL 标签、内嵌 SQL 编辑器、运行中的多语句结果和表页共享这一预算，同一结果按唯一身份只计费一次。接收时遍历 JSON 值估算列名与行矩阵的字节数，不构造完整 JSON 字符串副本；索引只保存字节数、访问顺序、保护计数和释放回调。

超出预算时，按最近使用顺序释放最旧且未受保护的行载荷。SQL、列名、成功或失败摘要以及表页的筛选、排序、页大小和滚动意图继续保留。多语句脚本每条结果返回后立即纳入预算，正在运行的脚本只保护最近返回的结果，后续语句仍按原顺序执行。

SQL 结果释放后显示“结果已释放，请重新执行以查看数据”，依赖完整行的操作不可用。缓存回收不会自动重跑 SQL。表浏览返回已释放页面时，会按保留的浏览条件重新加载；旧游标和行选择失效，避免把旧页选择套用到新数据。

当前可见结果、存在未提交修改的表页，以及复制、导出、编辑操作持有租约的数据受到保护。保护计数归零后立即重新检查预算；多个操作共用同一结果时须全部释放租约。所有结果均受保护时允许暂时超过 128 MiB，并暴露 `overBudget` 状态，不以丢失编辑来满足预算。

## 测量边界

128 MiB 只约束可回收行载荷的估算字节，不等于 JS heap、WebView 或整个应用 RSS。对象、字符串表示、驱动缓冲、导出工作簿和正在传输的数据还会占用内存。单条数据库协议消息仍可能先被驱动分配再接受检查，因此后端 32 MiB 也不是严格的进程峰值上限。

仍通过一次 Tauri 调用返回预算内结果。磁盘结果存储和 [Tauri Channels](https://v2.tauri.app/develop/calling-frontend/#channels) 分块传输不在本次范围内。可复现的合成结果测量、保护例外及实测限制见 [性能验证基线](performance-baseline.md)。

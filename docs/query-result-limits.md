# SQL 编辑器查询结果限制

SQL 编辑器以及执行计划查询使用统一预算，定义在 `src-tauri/src/db/result_budget.rs`：

- 最多 **100,000 行**，恰好达到上限可正常返回。
- 最多 **32 MiB**，按列名数组和行矩阵的紧凑 JSON UTF-8 字节数计算，包含转义、空值和数组分隔符。预算不等同于进程堆内存上限。
- 超过任一预算即返回中文错误，不把截断数据作为完整结果展示。可通过减少列、限制返回行数或缩小查询范围重试。

PostgreSQL 使用 `simple_query_raw` 逐条读取消息，直接生成最终行矩阵；MySQL、SQLite 和 SQL Server 逐行转换并检查预算。读取已有结果流不会为每行额外执行 SQL。

PostgreSQL 的取消信号会唤醒等待下一行的读取任务。超限或取消时发送取消请求（清理最多等待 2 秒），并移除该池连接；正常完成后禁用旧取消句柄，避免影响复用连接上的后续查询。MySQL 出错时关闭连接，不为清理而继续排空超限结果。SQL Server 结果读取失败时也关闭并淘汰连接，保留原有连接池容量限制，避免后续查询为了复用连接而继续排空旧结果。

ClickHouse 同时设置服务端行数与字节数上限，并对 HTTP 响应累积字节设置本地上限；响应包含元数据和统计信息，因此可能比最终行矩阵预算更早拒绝。解析后的结果仍需通过共享预算。

前端保留后端返回的二维数组，以总行数驱动分页，仅把当前页转换成表格记录；导出继续使用完整的已接收结果。

本次仍通过一次 Tauri 调用返回预算内的结果。单条数据库协议消息仍由驱动解码，不承诺严格的进程内存峰值上限。结果句柄、带有界缓冲的 [Tauri Channels](https://v2.tauri.app/develop/calling-frontend/#channels) 分块传输，以及非活动标签缓存淘汰留作后续优化。

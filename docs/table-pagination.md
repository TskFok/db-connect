# 表数据分页

表数据浏览支持混合分页。SQL 编辑器的结果分页不受此功能影响。

## 支持条件

第一期仅对 MySQL、PostgreSQL 中具有**单列整数主键**的表启用游标分页：

- 未指定排序时，按该主键升序显示。
- 仅按该主键排序时，保留用户选择的升序或降序。
- 上一页、下一页按钮使用当前成功加载页面的首尾游标。
- 点击数字页码、快速跳页、刷新数据、增删改后的重载使用 OFFSET，并重新生成游标。

主键值必须能从查询结果中读取。界面隐藏的主键会自动补查；MySQL 数据库级 `INVISIBLE` 主键若未出现在默认 `SELECT *` 结果中，则保留 OFFSET。

复合主键、非整数主键、其他列排序、多列排序以及没有可靠主键的表保留 OFFSET。PostgreSQL 普通继承父表也保留 OFFSET，因为父表主键不能保证所有子表合并后的唯一性。SQLite、SQL Server、ClickHouse 继续使用原分页行为。尤其不能将 ClickHouse 的主键视为唯一约束。

匹配排序和过滤条件的索引决定实际性能收益。游标分页减少深页顺序浏览时跳过记录的成本，不加速随机跳页或总行数统计，也不会自动修改用户数据库的索引。

## 数据与状态

游标由后端从原始整数值生成，不经过 JavaScript 数值转换，支持超出 JavaScript 安全整数范围的主键。前端只保存和透传不透明游标。游标与连接、表、筛选、排序、页大小和翻页方向绑定；失效或不可复用时回退到请求页的 OFFSET 查询。

游标暂存在应用内存中，五分钟后过期，缓存容量也有上限。因此长时间停留后继续翻页可能先执行一次 OFFSET。刷新或跳页重新读取主键元数据，后续连续翻页复用这些元数据，不逐列或逐索引查询 SQL。

排序、筛选、每页条数变化会清除当前游标；切换表时游标随页面快照恢复。加载时禁用分页按钮，迟到请求不能覆盖新的页面。失败后再次刷新会重新建立 OFFSET 基准。隐藏主键仍会在结果数据中保留，以维持行选择和编辑定位，但继续遵循界面的隐藏列设置。

可通过查询 SQL 按钮查看、复制后端实际执行的分页查询。上一页查询先按反向顺序读取，再恢复原显示顺序；复制的 SQL 反映实际读取顺序。

总数统计继续独立请求并缓存，分页总数可能在外部写入后过期。游标分页不提供跨页事务快照：并发修改排序键可能让记录跨越页面边界。需要重新定位时刷新数据，需要更新页数时刷新分页。

## MySQL 大字段按需加载

MySQL 表浏览在能够取得可靠、完整主键时，对超过 4 KB 的文本、JSON、字符串及二进制字段只返回短预览。预览在数据库查询中生成，因此首次打开表和后续分页都无需传输整段大字段；数据库仍可能需要读取原字段来计算预览。主键始终完整返回，隐藏列继续从查询投影中排除。

单元格会标明按需加载，双击后读取该行所需字段。完整文本加载成功后才允许编辑；加载失败、取消或者页面变化都不会把预览写回数据库。只读连接可以查看完整内容。二进制字段沿用已有展示方式，延迟加载的二进制字段仅允许查看，避免将二进制占位文本当作原值编辑。

复制 JSON、复制 INSERT 和导出当前页 Excel 时，所需完整值按主键批量查询，再生成输出；不会逐行发起 SQL。数据行被删除或主键变化导致回查失败时，会提示错误并停止操作，避免输出不完整数据。

完整行回查会补齐用于匹配的数据库级 INVISIBLE 主键，因此完整 INSERT 也可包含该主键；选择“不含主键”复制时仍会排除它。默认分页的不可见列行为不变。

无可靠完整主键的表、视图及无法安全回传主键值的表保留完整加载。其他数据库和 SQL 编辑器结果不受影响。完整值在用户请求时读取，可能比分页时更新，不构成跨请求事务快照。
